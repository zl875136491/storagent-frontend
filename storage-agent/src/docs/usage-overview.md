## 核心概念（与实现一致）

- **区域（Region）**：逻辑分区，用于归类 MinIO 与展示拓扑。
- **MinIO 服务**：真实对象存储节点；凭证等由平台托管，业务侧不直连 MinIO。
- **应用（Application）**：业务身份。创建后默认未启用；**授权**后才会在各站点落地应用桶并参与复制。
- **APIKey**：绑定到**已授权应用**的访问凭证。调用 `/api/files/*` 时放在 `x-api-key`。
- **存储桶 / 对象**：应用授权后，对象落在以应用命名的桶中；业务通过 `object_key` 读写，一般不自己选桶名。

> 注意：新建应用时**不再要求勾选关联区域**（旧文档中的「选择关联区域」已过时）。区域与 MinIO 由平台拓扑统一管理，授权流程会按当前拓扑准备资源。

## 按模块使用说明

### 区域管理

- 查看区域列表（名称、简称、ID）。
- **新建区域**：填写区域名称、区域简称。
- 创建/下线区域需要管理员侧的区域管理权限（管理员角色默认具备）。

### 应用管理

- **新建应用**：填写显示名称、APPID、描述 → 提交。
- 列表可见授权状态；未授权应用不能签发可用的业务 APIKey。
- **授权**：由具备应用管理能力的账号（通常是管理员）执行；过程为 SSE 进度流，会在各 MinIO 上准备桶、版本与复制等。
- 普通用户可创建自己的应用，但授权按钮在无权限时会由后端拒绝（403）。

### APIKey 管理

- 前置：至少一个**已授权且属于你**的应用（管理员可看到更广的密钥列表）。
- **新建**：选择应用、可选失效日期；成功弹窗中的明文 **只出现一次**。
- **吊销**：所有者可吊销自己的 Key；管理员可吊销他人 Key，对方列表会显示「被管理人员注销」。
- 列表中的 Key 为掩码，仅用于比对。

### MinIO 服务管理

- 登记各区域 MinIO（主机、端口、密钥、复制权重等）。
- 界面上的创建/改权重等写操作面向管理员；与后端 `region_manage` / 管理员校验一致。

### 存储桶管理（复制拓扑）

- 选择存储桶后展示跨站点复制关系图。
- **显示**：所有登录用户可查看。
- **编辑**（拖拽节点、增删复制边）：仅管理员；非管理员会看到编辑遮罩，后端亦会拒绝写位置/改关系请求。

### 服务器文件详情

- 选择某个 MinIO 服务后，以 Treemap 查看其下 Bucket 与目录占用。
- 用于容量排查，不替代业务侧的上传下载 API。

## 推荐业务接入流程

1. 业务同学登录 → **应用管理**新建应用。
2. 管理员在应用列表中完成 **授权**。
3. 业务同学在 **APIKey 管理**创建 Key，安全下发。
4. 开发同学用 Key 调文件接口，或参考「功能组件引导」中的 Demo。
5. 上线后可用「服务器文件详情」观察空间；跨站点同步问题看「存储桶管理」拓扑。

## 常见误解

| 误解 | 实际情况 |
|------|----------|
| 用 `Authorization: Bearer` 传 APIKey | 文件接口必须用 `x-api-key` |
| 创建应用时要选区域 | 当前创建表单无区域多选 |
| 普通用户也能改复制拓扑 | 仅管理员可编辑 |
| APIKey 可再次查看明文 | 仅创建时一次；之后只有掩码 |
| 开发人员使用指南里的 `/api/buckets` + Bearer 示例 | 已过时，请改看「功能接口引导」 |
